# Live-pass v0.27.0 fixes — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the sixteen defects Wyatt found in the first live pass over batches 12–16, on branch `fix/live-pass-0.27`, shipping as v0.28.0.

**Architecture:** Newtpad is ~11k lines of Odin, layered `base` → `platform` → `program`. Nothing here adds a layer or a dependency. Ten tasks fix a confirmed root cause; three begin with an instrumentation step that can *refute* the hypothesis before any code changes; one (Task 16) is a measurement whose honest outcome may be "no code change needed". Two tasks change geometry that every other task is drawn against, so they land first.

**Tech Stack:** Odin, D3D11 + DXGI flip-model, DirectWrite as glyph rasterizer only. Windows-only. No test framework beyond `odin test` for `src/base` and hand-rolled headless modes in `src/program/test_modes.odin`.

**Spec:** [2026-07-28-live-pass-0.27-fixes-design.md](../specs/2026-07-28-live-pass-0.27-fixes-design.md). Every task below cites its spec section. When the spec and this plan disagree, the spec is right and this plan is wrong — say so rather than silently following one.

## Global Constraints

- **Build:** `build.bat` = debug, console subsystem, so headless modes can print. `build.bat release` = the shipped GUI exe. A bare `odin build` omits the DPI manifest and is wrong for anything visual. **The exe is at `build\newtpad.exe`, not the repo root.**
- **Full rebuild must stay under ~5 s.** One build script. No build system sprawl.
- **Set `NEWTPAD_SESSION_DIR` to a temp directory before running any headless mode**, or the session modes write to the real store under `%APPDATA%\Newtpad`.
- **`Select-String "FAIL"` is case-insensitive** and matches "0 failures" in a passing summary. Always pass `-CaseSensitive`.
- **Every new test case goes in its own local proc.** `test_mode_dispatch` is one enormous procedure; a callee holding two `App` structs live at once has hit a real `STATUS_STACK_OVERFLOW` twice. Keep each proc to one `App`/`Document` at a time.
- **Argument order in test modes is per-mode and unforgiving.** The path comes FIRST for `keytest`/`edittest`/`seltest`. A file-argument mode with a missing argument falls through to opening the real GUI and hangs.
- **Sabotage every fix.** Write the fix and the test, reintroduce the bug, run the test, watch it fail, record the exact output, restore. "I verified it fails" without the output is not evidence. This is the highest-yield rule in the project.
- **Every commit must build.** If a commit changes a signature and another changes its callers, the branch is not bisectable.
- **Check `git diff --stat` before committing.** The Write/Edit tools have silently rewritten whole files CRLF→LF twice on one branch. Confirm the line count matches what you actually changed.
- **PowerShell 5.1 has no `&&`, no `||`, no ternary.** Use `; if ($?) { }`. For a commit message containing a quote, write it to a file and use `git commit -F`.
- **Commits are authored solely by Wyatt Guethlein.** Never `Co-Authored-By: Claude`, never "Generated with Claude Code", never a robot emoji, never any AI attribution — in commits, merges, tags or PR bodies.
- **Do not push.** Wyatt pushes, and only when he asks.

// Rows the DRAW emits: the fully visible ones, plus a partial row when the
// remainder can show any of it. Scissored to the content box by the caller, so
// a partial row cannot paint over the status bar.
//
// Deliberately separate from doc_visible_rows rather than replacing it.
// doc_visible_rows answers "how many rows are wholly on screen", which is the
// right question for the scroll clamp and the page keys -- paging by a count
// that includes a sliver would scroll a hair further each press. The draw and
// the HIT-TEST ask this one instead: a half-visible line is clickable, because
// it is on screen. Two questions, two procedures; conflating them is the §6j
// shape that has cost sixteen bugs.
doc_drawn_rows :: proc(doc: ^Document, height, line_h: f32) -> int {
	full := doc_visible_rows(doc, height, line_h)
	avail := height - CONTENT_TOP - TOP_INSET - doc_bottom_bar_h(doc)
	if avail - f32(full) * line_h > 0.5 {return full + 1}
	return full
}
```

In `src/program/lex_index.odin`:

```odin
// The fence-open line governing `before`, found through the per-line state
// index in O(log n): the largest recorded line start below `before` whose
// state transitions out-of-fence -> in-fence.
//
// Exists because Lex_State is a scalar. It can say we are INSIDE a fence, which
// is all markdown_draw needs to suppress parsing and paint the code
// background -- but not that the fence said `json`, and the tag is what picks
// the lexer. The transition point is where the tag is written down.
//
// Returns found=false when the index is absent or stale (a huge file, or an
// edit past built_for_revision). The caller degrades to an UNCOLOURED code
// block: still correctly a fence, just without syntax colours. That is honest
// and bounded. Scanning backward a fixed distance for a ``` instead would be
// the Shape A bug -- a fence can be arbitrarily far above the viewport, so a
// bounded backward scan returns a confident wrong answer.
lex_index_fence_open :: proc(doc: ^Document, before: int) -> (line_start: int, found: bool) {
	if !lex_index_valid(doc) {return 0, false}
	// ... binary search the index for the transition, return that line's start
}
```
